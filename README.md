# asd-ste100-ru — Упрощённый технический русский

Русскоязычный скилл для переписывания неоднозначного технического текста, который читают ИИ-агенты и системы: описаний инструментов, системных промптов, ошибок, статусов и межагентских инструкций. Основан на общих принципах контролируемого языка и идее [danyuchn/asd-ste100-skill](https://github.com/danyuchn/asd-ste100-skill), но русские правила и лексические списки разработаны отдельно.

> **Обязательная рамка:** ASD-STE100 определяет **только английский язык**. Официального русского стандарта ASD-STE100 **не существует**. Русская версия — **адаптация принципов, а не перевод стандарта**. Все правила, специально введённые для русского языка, являются **адаптацией проекта**, а не нормами ASD-STE100. Для официального применения стандарта скачайте документ бесплатно с [asd-ste100.org](https://asd-ste100.org/) и соблюдайте его условия использования.

Один каталог обслуживает несколько инструментов — формат `SKILL.md` общий для ZCode и Claude Code (оригинал создан именно для Claude Code). Отдельная копия для каждого инструмента не нужна: различается только папка установки.

## Что делает скилл

- Выделяет действия, исполнителей, условия и последствия, не добавляя новых фактов.
- Сохраняет модальность: «возможно», «мог», «вероятно», «как правило» не превращаются в факт.
- Убирает канцелярит, сленг, рекламные слова и неясные цепочки уточнений.
- Предлагает короткие инструкции с последовательными терминами и явными субъектами.
- Проверяет часть правил линтером на чистом Python без внешних библиотек.

**Не использовать** для художественной прозы и рекламного копирайтинга, где смысл зависит от выразительности.

## Установка

### ZCode

Скопируйте каталог `asd-ste100-ru` целиком в `~/.agents/skills/` (на Windows — `C:\Users\<имя>\.agents\skills\`), чтобы скилл был доступен во всех проектах, либо в `<проект>/.agents/skills/` — для одного проекта. Вызов: команда `/asd-ste100-ru <текст>` или автоматически по описанию скилла.

### Claude Code

Скопируйте каталог целиком в `~/.claude/skills/asd-ste100-ru/` или установите командой:

```bash
npx skills add erwinete/asd-ste100-ru
```

В репозитории есть манифест `.claude-plugin/plugin.json` для плагин-экосистемы Claude.

### ChatGPT и другие среды

Для ChatGPT предусмотрен `agents/openai.yaml`. В остальных средах скопируйте каталог целиком в папку локальных скиллов среды. Линтер запускайте с полным путём к `scripts/ste-lint.py`; на Windows используйте команду `python`.

### Ручная работа

Откройте `SKILL.md` и передавайте технический текст вместе с запросом «Упрости по СТИ, не меняй смысл».

### Глобальное поведение во всех сессиях (опционально)

Установка скилла даёт триггерное поведение: модель вызывает его при просьбах переписать текст. Чтобы ядро стиля действовало во всех задачах и сессиях по умолчанию (как у автора), добавьте готовый блок из [`INTEGRATION.md`](INTEGRATION.md) в пользовательский файл инструкций: ZCode — `~/.zcode/AGENTS.md`, Claude Code — `~/.claude/CLAUDE.md`. Это опционально и не требуется для работы скилла.

## Проверка линтером

```bash
python scripts/ste-lint.py --selftest
python scripts/ste-lint.py README.md
python scripts/ste-lint.py --json README.md
python scripts/ste-lint.py --baseline 2 README.md
python scripts/ste-lint.py --disable abbreviation,passive-voice README.md
python scripts/ste-lint.py --mode flavored README.md
printf '%s\n' 'Выполните проверку данных.' | python scripts/ste-lint.py
```

Поддерживаются аргументы файлов, stdin, `--json`, `--baseline`, `--disable`, `--selftest`, а также `--mode strict|flavored`. Флаги могут стоять между путями. Коды: **0** — число hard-нарушений не превышает `baseline`; **1** — превышает; **2** — неправильный аргумент либо файл не читается. Advisory не влияет на код выхода. В JSON доступны `violations`, `count`, `hard_count`, `baseline`, `words`, `per_100_words`.

### Режимы и терминология

- **Строгий режим (Strict)** — инструкции, сообщения об ошибках, tool descriptions и системные промпты. Ротация синонимов — hard.
- **СТИ-стилизованный режим (STE-flavored)** — README, документация, changelog. Ротация синонимов — advisory.
- **Контролируемый язык** — ограниченные лексические и структурные правила, рассчитанные на однозначную интерпретацию.
- **Инструкция** — повелительное высказывание с требуемым действием. **Описание** — объяснение системы и её поведения.
- **Канцелярит** — тяжёлые конструкции со слабыми глаголами; **номинализация** — замена действия отглагольным существительным.
- **Хедж** — языковое выражение неопределённости. Хеджи никогда не помечаются линтером.

## Тестирование и калибровка

Встроенный набор линтера покрывает все 11 автоматических правил (обнаружение и отрицательный пример), сохранение хеджей, сегментацию кириллических предложений, Markdown-конструкции и CLI:

```bash
python scripts/ste-lint.py --selftest
```

Регрессионный корпус в `tests/`:

```bash
python scripts/ste-lint.py tests/test-01-dirty.md   # ожидается 11 находок: 9 hard, 2 advisory
python scripts/ste-lint.py tests/test-02-clean.md   # ожидается 0 находок, код выхода 0
```

`test-01-dirty.md` содержит замешанные нарушения всех правил (канцелярит, точка с запятой, цепочка «который», сленг, рекламные эпитеты, висячий союз, деепричастие, сокращение); `test-02-clean.md` написан чисто и служит проверкой ложных срабатываний, включая сохранение хеджей.

Сквозная калибровка поведения: пять живых прогонов (автотриггер, форс-вызов с таблицей правил, глобальный стиль без скилла, отладка, бизнес-требования). Все правки по их результатам задокументированы в `CHANGELOG.md` (версия 1.0.1-ru); правила и пороги линтера не менялись. Стартовая калибровка на русскоязычных документах описана ниже.

## Таблица проверок

| ID | Что проверяется | Уровень |
|---|---|---|
| `semicolon` | Точка с запятой вне кода | hard |
| `long-sentence` | Более 22 слов в предложении | hard |
| `nominalization` | Слабый глагол + название действия | hard |
| `marketing-adjective` | Русские рекламные слова | hard |
| `slang-anglicism` | Русский техносленг и ненужные англицизмы | hard |
| `synonym-rotation` | Замена выбранного глагола синонимом из той же группы | hard / advisory |
| `dangling-conjunction` | Союз в конце пункта списка | hard |
| `kotoryj-chain` | Два или более слова с основой «котор-» в одном предложении | hard |
| `participle-deepri` | Типичные деепричастия в инструкциях | advisory |
| `passive-voice` | Избранные эвристики русских пассивных конструкций | advisory |
| `abbreviation` | т.е., т.д., т.п., напр., др. и т. п. | advisory |

**Ограничение длины:** **18 слов** в инструкции и **22 слова** в описании — стартовые проектные пороги, эмпирически проверенные на ограниченной выборке. Автоматически проверяется **только 22**, потому что надёжно классифицировать инструкцию без контекста нельзя. Цифра 18 остаётся ручным требованием.

## Русская языковая политика и отличия от английской версии

1. **Перепроектирована грамматика:** вместо английских времён — дисциплина вида русского глагола (manual) и осторожное предупреждение о деепричастии (advisory).
2. **Новый центр тяжести — канцелярит:** «выполнить проверку» → «проверить». Поиск основан на конкретных глаголах и объектах, а не на одном суффиксе.
3. **Вместо фразовых глаголов** проверяются русские сленговые глаголы. «Откатить» разрешено как технический термин.
4. **Русские многоэтажные конструкции:** родительные цепочки — manual; повторные придаточные с «который» — hard.
5. **Сокращения:** добавлено advisory на «т.е.», «напр.» и другие; сегментация дополнена русскими аббревиатурами и инициалами.
6. **Пределы длины:** предложены 18/22 вместо английских 20/25. Это не научно универсальные пороги.
7. **Синонимические группы созданы заново** с кириллическими словоформами. «Ошибка / сбой / отказ» намеренно не объединяются, поскольку могут обозначать разные технические события. Это осознанное отклонение от стартового списка примеров в ТЗ ради точности.
8. **Русский контент и примеры созданы с нуля**. Английский стандарт и его словарь не копируются.
9. **Техническая инфраструктура** воспроизводит подход оригинала: Markdown-блоки, fenced/inline code, таблицы, GitHub-алерты, координаты, CLI и коды выхода, но реализация Python написана заново.

## Ограничения

- **Чистый прогон линтера не доказывает сохранения смысла**. Он также не доказывает полноту, безопасность или отсутствие двусмысленности.
- Линтер не знает морфологии, ролей в предложении, семантики терминов и домена. Он использует конечные словари и регулярные выражения; некоторые формы будут пропущены.
- Правила «родительные цепочки», «вид глагола», «одна часть речи», «одна инструкция» и «одно понятие в абзаце» требуют ручной проверки.
- Эвристики деепричастий и пассива специально ограничены ради уменьшения ложных срабатываний. Не все их случаи будут обнаружены.
- Названия параметров, точные сообщения, кавычки и идентификаторы могут быть значимым контентом — исправления в них следует согласовать вручную.
- Правило «первый синоним закрепляет выбор» не знает, разные ли это действия; при различии смыслов оставляйте разные слова.
- Текущий сегментатор считает устойчивые сокращения нетерминальными. Поэтому в примере «... и т.д. Затем ...» он может не обнаружить границу; предпочтительно раскрывать сокращения.
- Не воспроизводим ASD-STE100 Issue 9 или его словарь; проект не предоставляет сертификацию соответствия.
