# Русские примеры «до / после»

Все примеры созданы для этого проекта. Они иллюстрируют **правила проекта**, а не цитируют ASD-STE100. При реальной правке сначала проверяй сохранение смысла. Ссылки `2.x` ведут к `references/writing-rules.md`.

## Часть 1. Отдельные правила

| Правило | До | После | Почему |
|---|---|---|---|
| 2.1, пассив, advisory | «Файл был удалён системой после проверки». | «После проверки система удалила файл». | Назван исполнитель, указан тот же порядок действий. |
| 2.2, сленг, hard | «Заскипайте повторную загрузку». | «Пропустите повторную загрузку». | Удалён жаргон при сохранении действия. |
| 2.3, одно действие, manual | «Откройте журнал и отправьте его администратору». | «Откройте журнал. Затем отправьте журнал администратору». | Отдельное действие на предложение, сохранён порядок. |
| 2.4, длина, hard | «Если обработчик получает новую версию конфигурации во время выполнения задания и конфигурация не прошла проверку, то обработчик должен записать сообщение об ошибке в журнал, после чего оставить старые параметры без изменений». | «Если новая конфигурация получена во время задания и не прошла проверку, обработчик записывает ошибку в журнал. Затем обработчик оставляет прежние параметры». | Убрана чрезмерная длина. Условия и последствия сохранены. |
| 2.5, точка с запятой, hard | «Агент читает файл; затем возвращает статус». | «Агент читает файл. Затем возвращает статус». | Удалена точка с запятой. |
| 2.6, цепочка «который», hard | «Это файл, который создал агент, который выполнил задачу». | «Этот файл создал агент. Этот агент выполнил задачу». | Убраны два придаточных без добавления неуказанного порядка событий. |
| 2.6, родительный падеж, manual | «Откройте журнал системы управления доступом приложения». | «Откройте журнал приложения. В журнале записывает события система управления доступом». | Требуется вручную проверить, что это тот же журнал и те же отношения объектов. |
| 2.7, деепричастие, advisory | «Проверив отчёт, отправьте его». | «Проверьте отчёт. Затем отправьте отчёт». | Скрытое действие сделано явным. |
| 2.7, вид глагола, manual | «Открывайте файл. Проверьте содержимое. Сохранять результат». | «Откройте файл. Проверьте содержимое. Сохраните результат». | В списке согласован совершенный императив. |
| 2.8, пропущенные части, manual | «При ошибке — повтор». | «Если произошла ошибка, повторите действие». | Телеграфное сообщение заменено полной инструкцией. Что именно повторять, требуется уточнить у автора. |
| 2.9, модальность, manual | «Возможно, запрос не выполнился из-за тайм-аута». | «Запрос мог не выполниться. Возможная причина — тайм-аут». | Причина остаётся предположением, а не установленным фактом. |
| 2.10, абзацы, manual | «Проверяйте статус и считывайте код и сохраняйте журнал. Модуль устанавливается на сервер и обновляется вручную». | «Проверяйте статус. Считывайте код. Сохраняйте журнал.\n\nМодуль устанавливается на сервер. Обновление выполняется вручную». | Разделены инструкция и описание установки. |
| 2.11, ротация, hard | «Проверьте входные данные. Затем валидируйте результат». | «Проверьте входные данные. Затем проверьте результат». | Если речь об одном действии проверки, используйте одно слово. Если проверка и валидация — разные операции, исходник следует сохранить. |
| 2.12, часть речи, manual | «Сохраните кеш. Затем кешируйте ответ». | «Сохраните кеш. Затем сохраните ответ в кеше». | Разделено имя хранилища и действие записи в него. |
| 2.13, канцелярит, hard | «Осуществите подключение к серверу». | «Подключитесь к серверу». | Слабый глагол и отглагольное существительное заменены действием. |
| 2.14, термин, manual | «Артефакт — файл результата задания. Запиши данные в артефакт. Затем прочитай файл результата». | «Артефакт — файл результата задания. Запишите данные в артефакт. Затем прочитайте артефакт». | Определение уже содержится в исходнике, а дальнейшее название используется единообразно. |
| 2.15, сокращение, advisory | «Отправьте отчёт, напр. JSON». | «Отправьте отчёт, например в формате JSON». | Сокращение раскрыто, но JSON как обозначение формата сохранён. |
| 2.17, маркетинговый эпитет, hard | «Инновационный модуль обрабатывает сообщения». | «Модуль обрабатывает сообщения». | Рекламное слово не содержит проверяемой характеристики. |
| 2.18, союз в списке, hard | «- Подготовьте запись и\n- Отправьте ответ». | «- Подготовьте запись\n- Отправьте ответ». | Устранён висячий союз в пункте Markdown-списка. |

**Замечание:** демонстрационные «после» в строках о падежах, телеграфном стиле и терминах показывают возможную правку, но её нельзя автоматически применять, пока исходный смысл не подтверждён. Проект запрещает достраивать незаданные факты.

## Часть 2. Сквозные примеры агентских текстов

### A. Описание инструмента агента — строгий режим

**До**

> Этот инструмент попытается синхронизировать состояние подключённых хранилищ, и если обнаружится конфликт, он, возможно, автоматически его разрешит в зависимости от настроенной стратегии либо передаст конфликт на ручную проверку.

**После**

> Инструмент пытается синхронизировать состояние подключённых хранилищ. Если инструмент обнаруживает конфликт, он проверяет настроенную стратегию. В зависимости от стратегии инструмент может разрешить конфликт автоматически. Если конфликт не разрешён, инструмент передаёт его на ручную проверку.

**Почему:** 2.3, 2.4, 2.1. Сохранены «пытается» и «может» (2.9). Условие ручной проверки сформулировано как результат: конфликт остался, а не как выдуманное новое правило.

### B. Сообщение об ошибке — строгий режим

**До**

> Возможно, запрос не был выполнен из-за ошибки сопоставления формата данных, которая могла возникнуть в связи с устаревшей версией клиента, хотя точная причина пока не установлена.

**После**

> Запрос мог не выполниться. Возможная причина — несоответствие формата данных. Оно могло возникнуть из-за устаревшей версии клиента. Точная причина пока не установлена.

**Почему:** 2.4, 2.6 и прежде всего 2.9. Все неизвестные обстоятельства остались неизвестными. **Модальность важнее вида и времени глагола**: «мог не выполниться» нельзя превращать в «не выполнился», даже если второй вариант проще.

### C. Межагентская инструкция — строгий режим

**До**

> После того как верхний агент закончит работу без ошибок, нижнему агенту нужно выполнить чтение файла с результатами, при этом при тайм-ауте возможно появление неполного файла.

**После**

> Дождитесь завершения верхнего агента без ошибок. Затем прочитайте файл результата. При тайм-ауте файл может быть неполным.

**Почему:** 2.3, 2.4, 2.13. Вероятность неполного файла сохранена (2.9). Новый шаг «проверьте целостность» **не добавлен**, так как его не было в оригинале.

### D. README — СТИ-стилизованный режим

**До**

> Наш передовой кеширующий компонент осуществляет интеллектуальное сопоставление похожих запросов и в результате обеспечивает бесшовную интеграцию с существующим окружением, а также способствует уменьшению количества повторных вычислений.

**После**

> Компонент кеша сопоставляет похожие запросы. Это помогает уменьшить число повторных вычислений. Компонент предназначен для интеграции с существующим окружением.

**Почему:** 2.4, 2.13, 2.17. Выражение «помогает уменьшить» сохраняет ограниченный характер утверждения. В этом режиме повторные понятные синонимы допускаются как рекомендация, если они не мешают смыслу.
